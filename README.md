# EvidenceFirst — 근거 기반 사업성과 분석

> 공개 재무·산업 데이터로 평가점수의 **90%** 를 계산하고, 근거가 확인된 생성형 AI 보조평가를 **10%** 만 반영하는 의사결정 지원 시스템.

최초 버전은 **점수**를 제공한다. 실제 결과 데이터와 시간순 검증을 확보한 뒤에만 정의된 사업성과의 **확률 예측**으로 확장한다.

> ⚠️ **상태: 설계 단계 (2026-10-06)** — 이 문서의 가중치·임계값·일정은 프로젝트용 초안이며 실증적으로 검증된 성공 공식이 아니다. 실제 API 연결, 데이터 수집, 모델 학습·검증은 아직 수행하지 않았다. 원본 설계는 `기업_프로젝트_성공가능성_분석_제안서.docx` (v1.0).

## 1. 해결하려는 문제

기업·사업 분석에서는 정보가 여러 보고서에 흩어져 있고, 분석자마다 지표와 기준이 다르며, AI가 근거 없이 "유망하다"는 결론을 내리기 쉽다. 산업이 다른 기업에 같은 기준을 적용하면 왜곡되고, 75점을 "성공확률 75%"로 표시하면 사용자가 오해한다.

시스템은 다음 질문에 답한다.

- 어떤 자료를 기준으로 분석했는가?
- 동일 업종과 비교할 때 강점과 약점은 무엇인가?
- 결과를 움직이는 지표와 가정은 무엇인가?
- 자료가 충분한가, 아니면 평가를 보류해야 하는가?
- 예측하려는 "성공"은 구체적으로 어떤 결과이며 언제 확인되는가?

**우선 사용자:** 사업기획·전략 담당자, 초기 창업자·프로젝트 기획자, 리서치·컨설팅 담당자, 포트폴리오를 검토하는 채용 평가자.

**대표 사용 흐름:** 기업 선택 → 비교군 확인 → 분석 기준일 선택 → 데이터 점검 → 지표 계산 → 보조분석 → 결과와 근거 확인

## 2. 핵심 결정

| 항목 | 결정 | 이유 |
|---|---|---|
| 첫 분석 대상 | 국내 상장 **전자부품 제조기업** 중 사업구조가 비슷한 비교군 | 공개 공시 활용, 업종 차이 최소화 |
| 최초 표본 | 파일럿 5개 → 비교군 20~40개 목표 | 데이터 품질을 직접 확인할 수 있는 규모 |
| 최초 출력 | 평가점수, 위험 신호, 비교표, 근거 보고서 | 검증 전에는 성공확률을 주장하지 않음 |
| 기업·프로젝트 | 데이터·근거 시스템은 공유, 점수 모형은 분리 | 기업 재무와 프로젝트 예산은 다른 변수 |
| 평가 원칙 | 구조화 지표 90% + LLM 정성평가 10% | AI가 계산식·가중치를 바꾸지 못하게 함 |
| 초기 스택 | Python + pandas + SQLite + Streamlit | 데이터와 계산을 먼저 완성 |
| 확장 | FastAPI → Docker → AWS → 작업 큐·모니터링 | 필요할 때 구조 추가 |
| 확률 모델 | 결과 라벨 확보 후 별도 단계 | 과거 결과·공시 시점 없이는 확률 검증 불가 |

## 3. 차별점

- 모든 점수를 **원본 자료와 계산식까지 역추적**할 수 있다.
- 같은 데이터·규칙 버전이면 구조화 점수가 **동일하게 재현**된다.
- 자료 부족을 낮은 실적으로 오해하지 않도록 **결측과 평가 불가를 구분**한다.
- AI 비중을 코드에서 **10%로 고정**하고 실제 영향도도 보여준다.
- PESTEL·SWOT을 **출처가 연결된 분석**으로 제공한다.
- 미래 정보 유입과 생존기업 편향을 검증 설계에서 다룬다.
- "확률처럼 보이는 점수"와 통계적으로 검증한 확률을 화면에서 구별한다.

## 4. "성공"의 정의

생존, 매출 성장, 수익성 개선, 기업가치 상승은 서로 다른 결과다. 결과를 먼저 정의하고 그에 맞는 지표·자료·모델을 고른다.

| 단계 | 출력 | 의미 |
|---|---|---|
| V1 | 사업성과 평가점수 0~100 | 현재·과거 자료를 정해진 규칙으로 요약 |
| V2 | 시나리오별 점수·현금흐름 변화 | 가정이 바뀔 때 계산 결과의 변화 |
| V3 | 정의된 사업성과 달성 확률 | 관측된 결과로 학습·검증한 조건부 확률 |
| 이후 | 생존·성장·현금창출 등 복수 결과 | 결과별 모형과 검증 보고서 |

**첫 확률 과제의 결과 정의 (제안):**
> 기준 사업연도 이후 두 개의 완료된 사업연도에서 2년 매출 CAGR이 대응 산업 매출 성장 대용지표를 초과하고, 2년 누적 영업현금흐름이 양수이면 "달성".

- 산업 매출 통계가 없으면 비교군 매출 CAGR 중앙값을 기준으로 쓰고 이름도 "비교군 대비 성장"으로 바꾼다. 두 기준을 섞지 않는다.
- 이 정의는 프로젝트의 선택이며 생존·투자수익률의 확률로 해석하지 않는다. 다른 목표는 새 `outcome_definition_version`으로 관리한다.

**프로젝트 성공(별도 모듈):** 수용 기준 충족, 완료일 준수, 예산 한도 준수, (사업화 시) 사용·매출 목표 달성. "개발 완료"와 "상업적 성공"은 별도 라벨이며, 목표 변경 시 변경 전·후와 사유를 기록한다.

| 영역 | 배점 | 역할 |
|---|---:|---|

### 6.1 재무 안정성·현금창출 (35)

| 지표 | 계산식 | 방향 | 배점 | 예외 |
|---|---|---|---:|---|
| OCF / 평균 총자산 | 연간 OCF ÷ (기초+기말 자산)/2 | 높을수록 | 10 | 평균자산 ≤ 0이면 보류 |
| 부채비율(총부채/총자산) | 총부채 ÷ 총자산 | 낮을수록 | 8 | 자산 ≤ 0 보류 |
| 이자보상배율 | 영업이익 ÷ 확인된 이자비용 | 높을수록 | 7 | 이자비용 0·미확인은 별도 상태 |
| 유동비율 | 유동자산 ÷ 유동부채 | 적정 범위 | 5 | 유동부채 0은 무한대 처리 금지, 상한 적용 |
| 현금 / 단기 이자부채 | 현금성자산 ÷ 단기 이자부채 | 높을수록 | 5 | 부채 0(확인됨)과 누락을 구분 |

### 6.2 성장성과 지속성 (20)

| 지표 | 계산식 | 방향 | 배점 | 예외 |
|---|---|---|---:|---|
| 3년 매출 CAGR | (최근 매출 / 3년 전 매출)^(1/3) − 1 | 높을수록 | 8 | 시작 매출 ≤ 0이면 미사용 |
| 비교군 대비 성장 격차 | 기업 CAGR − 비교군 CAGR 중앙값 | 높을수록 | 7 | 평가기업은 중앙값에서 제외 |
| 성장률 변동성 | 최근 3개 연간 성장률의 표준편차 | 낮을수록 | 5 | 지속 감소를 "안정"으로 표현하지 않음 |

### 6.3 운영 경쟁력 (20)

| 지표 | 계산식 | 방향 | 배점 | 예외 |
|---|---|---|---:|---|
| 영업이익률 우위 | 영업이익/매출 − 비교군 중앙값 | 높을수록 | 8 | 매출 ≤ 0 보류 |
| ROA 우위 | 순이익/평균 총자산 − 비교군 중앙값 | 높을수록 | 6 | 사업구조 차이 확인 |
| 재고회전율 우위 | (매출원가/평균 재고) ÷ 비교군 중앙값 | 적정 범위 | 6 | 재고·중앙값 ≤ 0 보류, 극단값 추가 보상 없음 |

### 6.4 시장·외부환경 (15)

| 지표 | 계산식 | 방향 | 배점 | 사용 조건 |
|---|---|---|---:|---|
| 대응 산업 매출 추세 | 관련 산업 동일 기간 매출 CAGR | 높을수록 | 8 | 명목·실질·산업 범위 일치 |
| 관련 업종 경기지표 변화 | 동일 통계계열 기준 기간 변화 | 해석된 방향 | 4 | 비교 가능한 공식 계열이 있을 때만 |
| 주요 투입가격 위험 | 투입가격 변동성 × 확인된 노출도 | 낮을수록 | 3 | 품목·노출 비중 확인 시에만 |

> 비교군 매출을 "산업 전체 매출"로 바꿔 채워 넣지 않는다. 맞는 자료가 없으면 결측으로 처리한다.

## 7. 정규화·결측·AI 실패 처리

### 7.1 0~100점 변환 (지표별로 규칙파일에서 선택)

- **A. 비교군 백분위** — 중간순위 방식. 평가기업은 비교군에서 제외.
  ```
  높을수록 유리: 100 × (x보다 작은 수 + 0.5 × 같은 수) / n
  낮을수록 유리: 100 − 위 점수
  ```
  n = 0이면 계산 불가, n < 20이면 작은 비교군 경보.
- **B. 고정 구간 선형 보간** — 적정 범위가 필요한 지표. 예: 유동비율 `0.5→0, 1.0→40, 1.5→70, 2.0→90, 3.0↑→90`
- **C. 조건부 점수** — 분모가 실제로 0인 정상 사례 등 정해진 예외에만. 누락 자료에는 적용하지 않음.

### 7.2 점수 계산

```
O               = Σ(w_i × s_i / 100)   # 구조화 기여도, 0~90 (Σw_i = 90)
objective_score = O / 0.90             # 구조화 평가만 0~100으로
ai_contribution = 0.10 × A             # A = AI 평가 0~100
final_score     = O + 0.10 × A         # 최종 평가점수 0~100
```

API와 화면에서 `objective_contribution`, `objective_score`, `ai_contribution`, `final_score`를 분리해 표시한다.

### 7.3 결측 처리

결측 지표의 가중치를 다른 지표로 **자동 재배분하지 않는다**. 대신 가능한 범위를 보여준다.

```
K = 계산 가능한 구조화 지표 기여도 합
M = 누락된 구조화 지표 배점 합
하한 = K + 0.10 × A
상한 = K + M + 0.10 × A
```

| 상태 | 조건 (가중 커버리지 = 계산 가능 배점 / 90) | 처리 |
|---|---|---|
| 충분 | 100%, 비교군·기간 기준 통과 | 정상 점수 |
| 부분 평가 | 80% 이상 100% 미만, 핵심 재무자료 존재 | 점수 범위, 순위 비교 제한 |
| 보류 | 80% 미만 또는 핵심 자료 부재 | 가능한 항목만 표시, 종합점수 보류 |

핵심 자료(매출·총자산·영업현금흐름·기준 기간·재무기준)가 없으면 커버리지가 높아도 보류한다. 이 범위는 통계적 신뢰구간이 아니다.

### 7.4 AI 평가 실패

구조화 점수는 정상 제공하고 AI는 "미제공"으로 표시한다. 구조화 비중을 조용히 100%로 바꾸지 않는다. AI 누락 범위는 `O ~ O+10`.

### 7.5 가중치 민감도

AI 10%는 고정. 구조화 네 영역 비중을 ±20% 상대 변화 후 90으로 재조정한 100~300개 시나리오에서 점수·순위 변화를 비교하고, 순위가 쉽게 뒤집히면 "가중치에 민감함"으로 표시한다.

### 7.6 예시 (가상 수치)

| 영역 | 영역 점수 | 배점 | 기여 |
|---|---:|---:|---:|
| 재무 안정성·현금창출 | 74 | 35 | 25.9 |
| 성장성과 지속성 | 68 | 20 | 13.6 |
| 운영 경쟁력 | 62 | 20 | 12.4 |
| 시장·외부환경 | 60 | 15 | 9.0 |
| AI 정성평가 | 75 | 10 | 7.5 |
| **합계** | | 100 | **68.4** |

화면 표시: `68.4/100` · 성공확률 **미제공** · AI 영향 중립 대비 **+2.5점**

## 8. AI 정성평가 10점 영역

| 항목 | 내부 비중 | 평가 질문 |
|---|---:|---|
| 전략 일관성 | 25% | 목표·자원·현재 사업 방향이 맞는가? |
| 사업모델 설명력 | 25% | 고객·가치·수익·비용 연결이 근거로 설명되는가? |
| 차별성의 증거 | 25% | 경쟁사 대비 차별성이 구체적 자료에 나타나는가? |
| 위험 인식·대응 | 25% | 확인된 위험에 대한 계획과 실행 근거가 있는가? |

- 루브릭: 0 · 25 · 50 · 75 · 100 · **미평가**. 근거 부족은 0점이 아니라 미평가. 네 항목이 모두 유효할 때만 정상 AI 점수.
- 출력은 구조화 JSON (`dimension`, `score`, `evidence_ids`, `reason`, `uncertainty`). `overall_score`는 서버가 재계산.
- 존재하지 않는 근거 ID·범위 밖 점수·누락 차원·잘못된 버전은 **검증 실패**.
- LLM은 점수 계산 함수·규칙파일·비교군 가중치에 접근하지 않는다. AI가 100점을 내도 최종 기여는 10점, 중립(50) 대비 변화는 **−5 ~ +5점**.
- 모델·프롬프트·루브릭·근거묶음 버전을 저장하고 동일 입력 결과는 캐시한다.
- 문서 속 "이전 지시를 무시하라" 같은 문장은 분석 대상 텍스트로만 처리한다.

## 9. 시장 분석·경쟁사 비교·위험 경보

**PESTEL** — 각 요소를 `근거 → 관측값 → 기업의 노출 → 예상 영향 → 불확실성`으로 표시. 방향은 유리·불리·혼재·불명확, 신뢰 상태는 확인·부분 확인·미확인. V1은 여섯 항목을 모두 숫자로 만들지 않으며, 이미 점수에 반영한 항목을 다시 더하지 않는다.

**HHI** — 정의된 시장의 점유율이 있을 때만 계산. 일부 경쟁사만 있으면 "표본 내 매출 집중도"로 구분. V1에서는 배경 지표로만 제시.

**비교군 선정** — 업종뿐 아니라 주요 제품·사업모델·시장·규모·제조 여부·회계기간을 확인. 편입·제외 사유와 선정일을 저장. AI는 후보를 추천할 수 있으나 자동 확정하지 않는다.

**SWOT** — S·W는 내부 특성과 비교군 지표, O·T는 외부 근거. "업계 선도", "독보적 기술"처럼 근거 없는 표현 금지. 회사 홍보자료에만 있는 주장은 "회사 측 설명"으로 표시. 항목 필드: `category, claim, evidence_ids, comparison_basis, verification_status, uncertainty`. SWOT은 가산점으로 쓰지 않는다.

**별도 위험 경보** (평균에 가려지지 않게 총점 옆에 표시):
- 확인된 자본잠식 또는 부채·자산의 중대한 이상
- 여러 기간 지속되는 영업현금흐름 적자
- 공시된 계속기업 관련 불확실성
- 주요 허가·계약·고객 상실에 관한 확인된 공시
- 핵심 재무자료 불일치 또는 미확인

## 10. 데이터 수집과 품질

### 10.1 데이터 소스

| 출처 | 내용 | 우선순위 |
|---|---|---|
| 금융감독원 **OpenDART** | 회사 식별, 공시 목록, 연간 재무제표·원문 | P0 (인증키 필요) |
| **KOSIS** 공유서비스 | 업종별 산업 통계 | P1 |
| 한국은행 **ECOS** | 경제·금융 통계 | P1 |
| 사업보고서·IR | 사업부문·고객·R&D·위험 | P0 원문 / P1 자동 추출 |
| 사용자 CSV | 프로젝트 예산·일정·인력 | P2 |
| 특허·규제자료 | 기술·환경·법적 노출 | P2 |

OpenDART 출발점: `corpCode.xml`(고유번호), `list.json`(공시 목록), `fnlttSinglAcntAll.json`(전체 재무제표). 사업보고서 기준 연간 자료, 연결 우선. 호출 제한은 설정파일로 관리하고 캐시·재시도·증분 수집을 사용한다.

### 10.2 수집 순서

1. 기업 5개로 실제 수집 가능성 확인 (매출, 영업이익, OCF, 총자산, 부채, 유동자산·부채, 재고, 현금, 이자비용)
2. 비교군 20~40개로 확장 (20개 미만이면 작은 표본 표시)
3. 산업 자료 연결 (실제 사업과 불일치하면 배경 설명으로만)
4. 확률 모델용 과거 시점 표본은 별도 수집

### 10.3 자료별 메타데이터

`entity_id`, `source_entity_id`, `period_start/end`, `published_at`, `collected_at`, `source_url`, `document_id`, `currency`, `unit`, `value`, `statement_basis`(연결/별도), `account_id`, `raw_account_name`, `revision_id`, `content_hash`, `verification_status`

> `collected_at`을 `published_at` 대신 쓰지 않는다. 오늘 수집한 2022년 정정 자료가 2022년에 이미 알려졌다고 간주하지 않는다.

### 10.4 정제 규칙

- 금액은 일관된 단위로 변환하고 원본 단위도 보존
- 표준 계정 ID로 매핑하되 이름 유사성만으로 확정하지 않음
- 손익·현금흐름의 기간과 자산·부채의 시점, 연결·별도를 섞지 않음
- 3년 CAGR에는 4개 연도 매출, 평균 자산·재고에는 기초·기말 값 필요
- 정정공시는 최신 분석용과 과거 시점 재현용을 분리
- 분모가 0 또는 음수인 지표는 단순 비율로 계산하지 않음
- 의심 자료는 삭제하지 않고 검토 대상으로 표시
- 해외 기업은 첫 버전에서 제외

## 12. 확률 모델 확장 조건

다음이 **모두** 충족되기 전에는 확률 표시를 활성화하지 않는다.

- 결과 정의·기간·라벨 규칙이 사전에 문서화됨
- 실제 결과가 관측된 기업·시점 표본 (탐색 목표 1,000개 이상 관측치)
- 성공·실패 양쪽 사례가 충분하고 미관측 사례가 분리됨
- 평가 당시 공개된 자료를 재현할 수 있음
- 상장폐지·합병 등 과거 모집단 처리 기록
- 시간순 검증·확률 보정·최종 테스트를 독립적으로 수행
- 단순 기저율보다 개선됨을 확인

**모델 순서:** 전체 기저율 → 업종·규모별 기저율 → 규칙 점수 단순 보정 → 로지스틱 회귀 → (필요 시) 부스팅

**검증:** 기준일 단위로 묶어 시간순 분리, 라벨 기간 겹침 제거, 전처리는 학습 구간에만 적합. 평가지표는 Brier Score·Log Loss(기저율 대비)·Calibration curve 중심, ROC-AUC·PR-AUC는 보조. "정확도 90%"를 목표로 두지 않는다.

**AI와 확률의 분리:** 최종 평가점수(90+10)와 사업성과 달성 확률(구조화 자료로 학습한 별도 모델)을 따로 제공한다. 확률 모델 기본 버전은 LLM 점수를 제외한다.
